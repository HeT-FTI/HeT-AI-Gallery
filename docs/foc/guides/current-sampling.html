1.1.9. Sampling and the power stage

The task: decide whether the current can be measured at all this switching period, understand what the bridge does to the voltage it was asked for, and get one diagnosis out of a bench session instead of a list of failures.

1.1.9.1. What you need

  • foc/core/single_shunt.hpp -- the sampling windows one DC-link shunt leaves you, and the three-valued verdict that comes with them.

  • foc/core/deadtime.hpp -- the phase-domain dead-time correction, its two shapes, and the estimator that identifies the fade width.

  • foc/core/board_check.hpp -- the measurands a bench session produces, and the mapping from a failure pattern to the one thing most likely wrong.

  • foc/core/trace.hpp -- a fixed-capacity ring of per-period samples. It records the currents and voltages the loop believed, one record per control period with the platform clock next to them -- which is also why it cannot answer a sampling-instant question on its own.

1.1.9.2. A minimal program

docs/doxygen/dox/demos/current-sampling.cxx sweeps the modulation index at three angles against the shunt verdict, reads the dead-time correction in two configurations, and runs the board check twice on the same measurements. The same file produces this page's figure.

  5// sources are part of the command, and `-Iinclude` alone fails at the link. A renamed

 36constexpr float kTSampleS = 0.2e-6F; // the ADC's aperture

 59    // ------------------------------------------------------------------ shunt
 60    // One DC-link shunt sees the current only while a particular switch pattern
 61    // is in force, so "is there a measurement this period" is a question about
 62    // the duties, not about the ADC. The answer depends on **where** the vector
 63    // points as much as on how big it is, so this sweeps the modulation index at
 64    // three angles instead of one.
 65    // 单电阻只在某个开关图样成立时才看得到电流，所以"这个周期有没有测量"是关于占空比的
 66    // 问题，不是关于 ADC 的。答案既取决于矢量有多长，也取决于它指向**哪里**，所以这里
 67    // 在三个角度上扫调制比，而不是只扫一个。
 68    const foc::core::SingleShunt shunt(foc::core::SingleShunt::Config{kTSettleS, kTSampleS, kTpwmS});
 69    std::printf("single shunt: settle %.2f us + sample %.2f us of a %.1f us period\n",
 70                static_cast<double>(1.0e6F * kTSettleS), static_cast<double>(1.0e6F * kTSampleS),
 71                static_cast<double>(1.0e6F * kTpwmS));
 72    std::printf("%6s %8s %10s %12s  %s\n", "angle", "m", "window (us)", "needed (us)", "verdict");
 73    constexpr int kAngles[] = {0, 20, 30};
 74    for (const int angle_deg : kAngles) {
 75        const float angle_rad = (kTwoPi / 360.0F) * static_cast<float>(angle_deg);
 76        int previous_verdict = -1;
 77        for (int step = 0; step <= 100; ++step) {
 78            const float m = 0.01F * static_cast<float>(step);
 79            const float magnitude_v = m * kVBusV;
 80            const foc::core::SvpwmResult modulated = foc::core::Svpwm::modulate(
 81                foc::core::Ab<float>{magnitude_v * std::cos(angle_rad), magnitude_v * std::sin(angle_rad)}, kVBusV);
 82            const foc::core::ShuntWindow window = shunt.classify(modulated.duty);
 83            const int verdict = static_cast<int>(window.verdict);
 84            if (csv != nullptr) {
 85                std::fprintf(csv, "shunt%d,%.4f,%.4f,%d,%.4f\n", angle_deg, static_cast<double>(m),
 86                             static_cast<double>(1.0e6F * window.window_s), verdict,
 87                             static_cast<double>(1.0e6F * window.needed_s));
 88            } else if (verdict != previous_verdict || (step % 25) == 0) {
 89                static const char *names[] = {"measurable", "window too narrow", "no active vector"};
 90                std::printf("%6d %8.2f %10.3f %12.3f  %s\n", angle_deg, static_cast<double>(m),
 91                            static_cast<double>(1.0e6F * window.window_s),
 92                            static_cast<double>(1.0e6F * window.needed_s),
 93                            names[(verdict >= 0 && verdict <= 2) ? verdict : 0]);
 94                previous_verdict = verdict;
 95            }
 96        }

 99    // --------------------------------------------------------------- dead time
100    // The bridge cannot deliver what it is told: every edge costs `t_dead` of the
101    // period on the phase whose current sign it contradicts. `deadtime_v` is that
102    // loss expressed as a voltage, and the correction is per phase because the
103    // loss is per phase.
104    // 桥臂交付不了它被告知的电压：每个边沿在"电流符号与之相反"的那一相上吃掉一个
105    // `t_dead`。`deadtime_v` 是这份损失折算成的电压，而修正在**相域**做，因为损失属于
106    // 每一相。
107    const float deadtime_v = (kTDeadS / kTpwmS) * kVBusV;
108    constexpr float kMinCurrentA = 0.02F;
109    constexpr float kFadeA = 0.0355F; // the width the estimator returns on 24 V
110
111    // A modulator that only scales -- `duty = inv_clarke(v_ab)/v_bus + 0.5`, no
112    // common-mode redistribution. Wrapping *this* makes the duty difference equal
113    // the correction itself, measured in the phase where it is applied. With a real
114    // SVPWM in between, moving one phase also moves the common mode, and the duty
115    // you read back is only part of what was added -- which is exactly why the
116    // correction belongs in the phase domain and has to be measured there.
117    // 一个只做缩放的调制器：`duty = inv_clarke(v_ab)/v_bus + 0.5`，不做共模重分配。包在它
118    // 外面，占空比之差**就是**修正本身，而且是在它被施加的那一相上量的。中间夹一个真的
119    // SVPWM 时，抬一相也会抬共模，你读回来的占空比只是加进去的一部分——这正是修正在相域
120    // 做、也必须在相域量的原因。
121    struct PassThrough final {
122        [[nodiscard]] static auto modulate(const foc::core::ModulatorInput &request) noexcept
123            -> foc::core::SvpwmResult {
124            const foc::core::Uvw<float> v_uvw = foc::core::inv_clarke(request.v_ab);
125            const float per_volt = (request.v_bus > 0.0F) ? (1.0F / request.v_bus) : 0.0F;
126            auto duty_of = [per_volt](float volt) noexcept -> float {
127                const float duty = 0.5F + (volt * per_volt);
128                if (!(duty > 0.0F)) {
129                    return 0.0F;
130                }
131                if (!(duty < 1.0F)) {
132                    return 1.0F;
133                }
134                return duty;
135            };
136            return foc::core::SvpwmResult{
137                foc::core::Uvw<float>{duty_of(v_uvw.u), duty_of(v_uvw.v), duty_of(v_uvw.w)}, false,
138                foc::ErrorCode::Ok};
139        }
140    };

142    using PhaseDomain = foc::core::DeadTimeCompensator<PassThrough>;
143    const PhaseDomain stepped(PhaseDomain::Config{deadtime_v, kMinCurrentA, 0.0F});
144    const PhaseDomain ramped(PhaseDomain::Config{deadtime_v, kMinCurrentA, kFadeA});
145    const PhaseDomain off(PhaseDomain::Config{0.0F, kMinCurrentA, 0.0F});
146
147    const foc::core::Ab<float> request{6.0F, 2.0F};
148    std::printf("\ndead time %.0f ns of a %.1f us period -> deadtime_v = %.3f V\n",
149                static_cast<double>(1.0e9F * kTDeadS), static_cast<double>(1.0e6F * kTpwmS),
150                static_cast<double>(deadtime_v));
151    if (csv == nullptr) {
152        std::printf("%10s %16s %16s\n", "|i_u| (A)", "step (V, a-b)", "ramp (V, a-b)");
153    }
154    // The two configurations only disagree inside one band -- between
155    // `min_current_a` (below it neither corrects) and `i_fade_a` (above it both
156    // saturate) -- so the sweep is dense there and coarse above it. That band *is*
157    // the whole difference, and it is 15 mA wide on this hardware.
158    // 两个配置只在一个带里不同：`min_current_a` 以下都不修，`i_fade_a` 以上都饱和。所以
159    // 在那个带里加密、上面放宽。那个带**就是**全部差别，本机上是 15 mA 宽。
160    for (int step = 0; step <= 200; ++step) {
161        const float i_magnitude = (step <= 60) ? 0.001F * static_cast<float>(step) : 0.06F + 0.002F * static_cast<float>(step - 60);
162        // The current on the phase being measured goes from 0 upwards; the other two
163        // carry what is left, so the set stays balanced and the correction on each
164        // phase is the one that phase's own sign asks for.
165        // 被测那一相的电流从 0 往上；另两相带走剩下的，保持平衡，每相的修正就是它自己符号
166        // 所要求的那个。
167        const foc::core::Uvw<float> currents{i_magnitude, -0.5F * i_magnitude, -0.5F * i_magnitude};
168        const foc::core::ModulatorInput input{request, kVBusV, currents};
169        const foc::core::SvpwmResult base = off.modulate(input);
170        const foc::core::SvpwmResult with_step = stepped.modulate(input);
171        const foc::core::SvpwmResult with_ramp = ramped.modulate(input);
172        const float step_v = std::fabs(with_step.duty.u - base.duty.u) * kVBusV;
173        const float ramp_v = std::fabs(with_ramp.duty.u - base.duty.u) * kVBusV;
174        if (csv != nullptr) {
175            std::fprintf(csv, "dead,%.4f,%.6f,0,%.6f\n", static_cast<double>(i_magnitude),
176                         static_cast<double>(step_v), static_cast<double>(deadtime_v));
177            std::fprintf(csv, "ramp,%.4f,%.6f,0,%.6f\n", static_cast<double>(i_magnitude),
178                         static_cast<double>(ramp_v), static_cast<double>(deadtime_v));
179        } else if ((step % 20) == 0 || (step > 18 && step < 40 && (step % 2) == 0)) {
180            std::printf("%10.3f %14.4f %14.4f\n", static_cast<double>(i_magnitude), static_cast<double>(step_v),
181                        static_cast<double>(ramp_v));
182        }
183    }
184
185    if (csv != nullptr) {
186        std::fclose(csv);
187        std::printf("wrote %s\n", csv_path);
188        return 0;
189    }

192    // A bench session produces numbers, not verdicts -- and "two items failed" is
193    // not actionable. The measurand that points at *this* example is the one the ADC
194    // sees: if the sampled ripple is much larger than the switching period implies,
195    // the sample is landing off the centre of the zero vector.
196    // 一次台架测量给出的是数字，不是结论——而"两项失败了"没法处理。指向**本示例**的那个
197    // 被测量就是 ADC 看到的东西：如果采到的纹波远大于开关周期应有的值，采样点就落在零矢量
198    // 中心之外。

200    measured.sum_current_a = 0.004F;
201    measured.offset_a[0] = 0.001F;
202    measured.offset_a[1] = -0.002F;
203    measured.offset_a[2] = 0.001F;
204    measured.ripple_expected_a = 0.10F;
205    measured.ripple_measured_a = 0.22F; // the one this example is about
206    measured.deadtime_v = deadtime_v;
207    measured.deadtime_cmd_v = deadtime_v;
208    measured.encoder_offset_rad = 0.003F;
209    measured.rs_ohm = 1.02F;
210    measured.rs_nameplate_ohm = 1.00F;
211    measured.psi_f_wb = 0.0101F;
212    measured.psi_f_nameplate_wb = 0.0100F;
213    measured.observer_error_rad = 0.02F;

216    // inverted, which is the failure the report names first *and* the one that
217    // hides the rest: an inverted channel makes the ripple comparison meaningless.
218    // Fix it and the next session names a different cause -- which is what a
219    // diagnosis is for.
220    // 同一块板子的两次测量。第一次留了一个通道符号反了，那是报告最先指出的一项，**也是**
221    // 遮蔽其余项的那一项：符号反了之后纹波比较就没意义了。修好它，第二次会话就会指出
222    // 另一个成因——诊断的用处就在这里。
223    for (int session = 0; session < 2; ++session) {
224        measured.response_sign[0] = 1.0F;
225        measured.response_sign[1] = (session == 0) ? 1.0F : -1.0F;
226        measured.response_sign[2] = (session == 0) ? 1.0F : -1.0F;

254    std::printf("  demanded on each phase     %.3f\n", static_cast<double>(deadtime_v));
255    std::printf("  visible in alpha-beta      %.3f\n", static_cast<double>(alpha_beta_v));
256    std::printf("  visible in U's duty (SVPWM) %.3f\n", static_cast<double>(duty_v));

258                "because all three contribute along the same axis: %.3f V\n",
259                static_cast<double>((4.0F / 3.0F) * deadtime_v));

261    // What the two shapes do differently, in words that match the figure.
262    // 两种形状的差别，用与图一致的说法。
263    std::printf("step: 0 below %.0f mA, then full deadtime_v everywhere\n", static_cast<double>(1.0e3F * kMinCurrentA));
264    std::printf("ramp: 0 below %.0f mA, linear to %.1f mA, then full\n", static_cast<double>(1.0e3F * kMinCurrentA),
265                static_cast<double>(1.0e3F * kFadeA));
266    std::printf("the step jumps twice, not once: U leaves its dead band at %.0f mA, V and W at %.0f mA, "
267                "because they carry half the current\n",
268                static_cast<double>(1.0e3F * kMinCurrentA), static_cast<double>(2.0e3F * kMinCurrentA));
269    return 0;

1.1.9.3. Where the numbers come from

  • The settling time and the sampling time are your ADC's and your gate driver's, not the library's. Together they are the number every window is compared with, so they decide whether a topology is usable at your switching frequency at all.

  • The switching period turns duties into seconds, and it is also the denominator of the dead-time voltage: the loss is t_dead / T_pwm of the bus, so the same nanoseconds cost twice as much at half the frequency.

  • The fade width is the one number nobody can compute from a nameplate. predicted_ripple_a() is an upper bound that is wrong by an order of magnitude, and DeadTimeFadeEstimator is what replaces it -- with a result whose own header advises against using it.

  • The board limits are tolerances, kept separate from the measurements so a saved session can be re-judged without being re-run.

1.1.9.4. How it goes wrong

  1. The window read as a function of amplitude only. It is a function of the vector's angle as well. At a sector boundary two phases carry the same duty, one of the two active intervals is exactly zero, and no modulation index makes it measurable -- the sweep in the figure's left panel sits on the axis for every request. A design that validated its sampling at one operating point has validated one operating point.

  2. A correction measured in the wrong frame. The library adds its correction per phase, then projects back to alpha-beta to reach the modulator, and that projection drops the part common to all three phases -- which a floating star point cannot see either. Read the same correction in one phase's duty and the modulator's own common-mode shift takes another bite. The example prints the same number three ways; a measurement note that does not say which frame it used cannot be reproduced.

  3. "Measurable" treated as a boolean. The verdict has three values, and the two failures are not the same failure: a narrow window can be waited for, an empty one means the pattern itself gives nothing to sample, so the answer is a different sampling instant rather than a longer one.

  4. Trusting an identified parameter because it is identifiable. The fade width can be identified and it still loses to the plain step; the header records both the comparison and the reason. Identifiability says the number exists, not that the model it belongs to is the right shape.

  5. A report that lists failures instead of naming a cause. Two inverted phases make the ripple comparison meaningless, so a session can fail three items and still have one thing to fix. The example runs the check before and after fixing it, and the second session names a different item -- which is the only way to know the first diagnosis was right.

1.1.9.5. Evidence

Four claim rows cover this page -- foc/core/single_shunt.hpp, foc/core/deadtime.hpp, foc/core/trace.hpp and foc/core/board_check.hpp -- and the level this page may state is the minimum of those four. The numbers behind the window sizes, the identified fade width and the diagnosis mapping live in those rows and in their test files, not on this page.

What this page does not claim: any compensation for the blind sector. No phase shifting, no second shunt and no prediction from the previous period is implemented, so the page describes what the window costs rather than how to recover it, and the dead-time fade it identifies is a width rather than a correction law.

1.1.9.6. Figure

The figure is produced by docs/demos/make_figures.py from this page's own example. The "settle + sample" line and the per-phase deadtime_v line both come out of the CSV's limit column, so they are the configuration the run used rather than constants typed into the plot. What the figure does not show is the hardware the numbers describe: no ADC samples here, no ringing, and the flat top of each window curve is the modulator clamping rather than anything the shunt does. Whether the ramp beats the step on a real bridge is a switching-plant measurement, and it lives in the claim row.
