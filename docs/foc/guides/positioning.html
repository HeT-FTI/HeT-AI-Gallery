1.1.8. Positioning an axis

The task: move a joint to a position, inside a window it must never leave, fast enough to be useful and gently enough not to excite the mechanics.

1.1.8.1. What you need

  • foc/core/soft_limit.hpp -- admit or refuse a target. Refusing is the whole point: a limit that clamps instead hands the loop a position it was never asked for.

  • foc/core/motion_profile.hpp -- shape a velocity command for the remaining error, under a velocity and an acceleration ceiling.

  • foc/core/position.hpp -- the P law that turns a position error into a velocity or torque command.

  • foc/core/position_reference.hpp -- unwraps the encoder and defines the origin; the first sample is the origin, which is why an axis without homing has an arbitrary one.

  • foc/core/homing.hpp -- finds a real origin, so the numbers mean something after a power cycle.

  • foc/core/gear_ratio.hpp -- one master angle in, a slave target and a slave velocity reference out.

1.1.8.2. A minimal program

docs/doxygen/dox/demos/positioning.cxx shows the two refusals, one gear sample and one shaped move. The same file produces this page's figure.

  1// Positioning -- positioning: admit a target, shape a velocity for it, and know
  2// where the axis may go. No plant: the "axis" below is a bare integrator, so what
  3// you are looking at is the profile's shape and the limit's refusals, not a motor.
  4//
  5// Build it the way the `demo` gate does -- the example calls into the library, so the
  6// sources are part of the command, and `-Iinclude` alone fails at the link. A renamed
  7// source turns that gate red instead of leaving a stale instruction here:
  8//   g++ -std=c++17 -fno-exceptions -fno-rtti -Wall -Wextra -Werror -Iinclude
  9//   docs/doxygen/dox/demos/positioning.cxx src/core/*.cpp
 10//   src/core/observer/*.cpp src/motor/*.cpp src/driver/*.cpp src/api/foc_api.c
 11//   src/api/bridge.cpp src/version.c
 12//   -o /tmp/positioning
 13//
 14// With `--csv <path>` it writes the same run as rows; that is how
 15// `docs/demos/make_figures.py` draws this example's figure.
 16//
 17// 定位 —— 定位：接纳一个目标、为它塑造一条速度、并知道轴能去哪。没有被控对象：下面的
 18// "轴"只是一个纯积分器，所以看到的是速度轮廓的形状与限位的拒绝，不是一台电机。
 19// 带 `--csv <path>` 时把同一次运行写成行；`docs/demos/make_figures.py` 正是这样画本片的图。
 20
 21#include <cmath>
 22#include <cstdio>
 23#include <cstring>
 24
 25#include <foc/core/gear_ratio.hpp>
 26#include <foc/core/motion_profile.hpp>
 27#include <foc/core/soft_limit.hpp>
 28#include <foc/core/types.hpp>
 29
 30namespace {
 31
 32constexpr float kDtS = 5.0e-5F; // 20 kHz, the loop this profile is shaped for
 33constexpr float kWallLowRad = -1.0F;
 34constexpr float kWallHighRad = 1.0F;
 35
 36/// The shaping law's three numbers, named once. `shaping_gain` is velocity per
 37/// radian of error (1/s), which is why it has the dimension of a bandwidth: the
 38/// axis closes about that fast to a small error.
 39/// 塑造律的三个数只写一次。`shaping_gain` 是"每弧度误差对应的速度"（1/s），所以它的量纲
 40/// 就是带宽：轴以大约那个速度收敛到小误差。
 41auto shaping() noexcept -> foc::core::MotionProfile::Config {
 42    foc::core::MotionProfile::Config config{};
 43    config.shaping_gain_rad_s = 8.0F;
 44    config.velocity_limit_rad_s = 5.0F;
 45    config.accel_limit_rad_s2 = 20.0F;
 46    return config;
 47}
 48
 49} // namespace
 50
 51auto main(int argc, char** argv) -> int {
 52    const char* csv_path = nullptr;
 53    if (argc == 3 && std::strcmp(argv[1], "--csv") == 0) {
 54        csv_path = argv[2];
 55    } else if (argc != 1) {
 56        std::fprintf(stderr, "usage: %s [--csv <path>]\n", argv[0]);
 57        return 2;
 58    }
 59
 60    foc::core::SoftLimit limit(foc::core::SoftLimitConfig{kWallLowRad, kWallHighRad});
 61    foc::core::MotionProfile profile(shaping());
 62
 63    // Two refusals first, because they are what the limit exists for. An
 64    // out-of-range target comes back as the *previous* target with `Param`, so
 65    // nothing downstream ever sees a position it would drive into a wall.
 66    // 先看两处拒绝，因为限位存在的意义就在这里。越界目标回来的是**上一个**目标并带
 67    // `Param`，因此下游任何东西都不会看到一个会把它驱进墙里的位置。
 68    const foc::core::SoftLimitOutput inside = limit.apply(0.5F);
 69    const foc::core::SoftLimitOutput outside = limit.apply(1.5F);
 70    const foc::core::SoftLimitOutput on_wall = limit.apply(kWallHighRad);
 71
 72    // The gear: one master angle in, the slave's target and its velocity
 73    // reference out. The velocity output is not a convenience -- a position loop
 74    // told only where to be lags a moving target, and this is the term that
 75    // cancels the lag.
 76    // 齿轮：一个主轴角度进，从轴目标与它的速度参考出。速度输出不是便利项——只被告知
 77    // "该在哪"的位置环跟随移动目标会滞后，而这一项正是抵消滞后的那个。
 78    // Two samples on purpose: the first one *defines* the origin, so its
 79    // velocity is zero by construction. Printing only that one would make a
 80    // working gear look broken.
 81    // 故意喂两个采样：第一个**定义**原点，所以它的速度按构造就是零。只打印它会让一个
 82    // 正常的齿轮看起来是坏的。
 83    foc::core::ElectronicGear gear(foc::core::GearConfig{2.0F, 0.1F});
 84    const foc::core::GearOutput origin = gear.apply(0.25F, kDtS);
 85    const foc::core::GearOutput geared = gear.apply(0.2505F, kDtS);
 86    (void)origin;
 87
 88    FILE* csv = nullptr;
 89    float t_s = 0.0F;
 90    float theta_rad = 0.0F;
 91    int rows = 0;
 92
 93    if (csv_path != nullptr) {
 94        csv = std::fopen(csv_path, "w");
 95        if (csv == nullptr) {
 96            std::perror("fopen");
 97            return 1;
 98        }
 99        std::fprintf(csv, "t_s,target_rad,velocity_rad_s,position_rad\n");
100    } else {
101        std::printf("soft limit [%.1f, %.1f] rad\n", static_cast<double>(kWallLowRad),
102                    static_cast<double>(kWallHighRad));
103        std::printf("  apply( 0.5) -> status %2d  target %+.3f rad\n", static_cast<int>(inside.status),
104                    static_cast<double>(inside.target_rad));
105        std::printf("  apply( 1.5) -> status %2d  target %+.3f rad  (refused, previous target returned)\n",
106                    static_cast<int>(outside.status), static_cast<double>(outside.target_rad));
107        std::printf("  apply( 1.0) -> status %2d  target %+.3f rad  at_wall=%s\n\n", static_cast<int>(on_wall.status),
108                    static_cast<double>(on_wall.target_rad), on_wall.at_wall ? "true" : "false");
109        std::printf("gear 2:1, offset 0.1: master 10 rad/s (0.5 mrad per period) -> slave %+.4f rad, "
110                    "velocity %+.4f rad/s\n\n",
111                    static_cast<double>(geared.slave_rad), static_cast<double>(geared.slave_velocity_rad_s));
112        std::printf("%8s %10s %12s %12s\n", "t (ms)", "target", "v cmd (rad/s)", "position (rad)");
113    }
114
115    // One move: ask for 0.5 rad and let the profile shape the approach. The
116    // integrator below is the whole "plant" -- it is a kinematic identity, not a
117    // motor model, which is why the figure shows a shape and not a dynamic.
118    // 一次运动：要 0.5 rad，让轮廓塑造整个接近过程。下面的积分器就是全部"被控对象"——
119    // 它是运动学恒等式，不是电机模型，所以图上看到的是形状而不是动态。
120    const float target_rad = inside.target_rad;
121    while (t_s < 1.5F) {
122        const float velocity = profile.step(target_rad, theta_rad, kDtS);
123        theta_rad += velocity * kDtS;
124        t_s += kDtS;
125        if (csv != nullptr) {
126            std::fprintf(csv, "%.6f,%.6f,%.6f,%.6f\n", static_cast<double>(t_s), static_cast<double>(target_rad),
127                         static_cast<double>(velocity), static_cast<double>(theta_rad));
128        } else if ((rows % 400) == 0) {
129            std::printf("%8.2f %10.3f %12.4f %12.5f\n", static_cast<double>(1000.0F * t_s),
130                        static_cast<double>(target_rad), static_cast<double>(velocity), static_cast<double>(theta_rad));
131        }
132        ++rows;
133    }
134
135    if (csv != nullptr) {
136        std::fclose(csv);
137        std::printf("wrote %s (%d rows)\n", csv_path, rows);
138        return 0;
139    }
140
141    std::printf("\nfinal position %.5f rad after %.2f s, residual %.5f rad\n", static_cast<double>(theta_rad),
142                static_cast<double>(t_s), static_cast<double>(target_rad - theta_rad));
143    return (std::fabs(target_rad - theta_rad) < 1.0e-3F) ? 0 : 1;
144}

The output to read first is the refusal: a target of 1.5 rad against a window of [-1.0, 1.0] comes back as Param and as the previous target. A caller that ignores the status goes on commanding the old position, and the axis holding still looks exactly like an axis that arrived.

1.1.8.3. Where the numbers come from

  • The window comes from the mechanics, not from the controller: where the axis physically may go. The walls are inclusive, so "move to the limit" is a command the limit can accept.

  • The acceleration ceiling is what the mechanics and the current limit allow. The velocity ceiling is usually the same number times a time constant; it exists so a large error cannot ask for a speed the loop cannot stop from.

  • The shaping gain has the dimension of a bandwidth (velocity per radian of error, 1/s), and it is the one number here that a user tunes. It is not the same knob as the position loop's gain: the profile shapes the command, the loop follows it.

  • The gear ratio and offset come from the mechanics; the offset is the slave position at master zero, so it is a measurement, not a preference.

1.1.8.4. How it goes wrong

  1. The refusal is ignored. Param plus the previous target is a safe answer only if the caller reads the status; otherwise the axis parks and the application believes it is moving. Check the status on every call, not the target value.

  2. A gear without the velocity reference. A position loop told only where to be lags a moving target by v * kd / kp; on a geared pair that lag is a synchronisation error that no gain increase fixes without also raising the noise. Feed the slave velocity forward.

  3. An origin nobody defined. position_reference defines the origin from the first sample, so an axis that never homed has a legal but arbitrary zero. Everything downstream -- soft limits included -- is then measured from the wrong place.

  4. Shaping treated as the loop. The profile limits how fast the command moves; it says nothing about the axis. A profile tuned to the acceleration limit with a loop that cannot track it produces a shaped command and an unshaped motion.

1.1.8.5. Evidence

Six claim rows cover this page -- soft_limit, motion_profile, position, position_reference, homing and gear_ratio -- and the level this page may state is the minimum of those six. The levels themselves are read from the claim table in the project README.md.

What this page does not claim: an absolute position before the first index mark, which does not exist; protection for an axis already past a wall, or for a window that moves inward around an axis already inside the new margin; or a following-error law against a trajectory this library does not generate.
