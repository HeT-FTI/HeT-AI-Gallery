1.1.5. Above base speed

The task: the axis has to keep producing torque past the speed where the voltage ceiling stops it. Decide whether it is worth implementing, and if it is, know what the currents have to do.

1.1.5.1. What you need

  • foc/core/mtpv.hpp -- the operating-region solver: the MTPA point, the base speed, and where the voltage ellipse and the current circle each bind.

  • foc/core/field_weakening.hpp -- the running policy, which produces the dq reference at whatever speed the axis is actually at, plus its refusal semantics.

  • foc/core/machine_map.hpp -- the nameplate as a function of current, for a machine whose inductance saturates. Optional: without it the solver uses the linear nameplate, which is what this page's example does.

1.1.5.2. A minimal program

docs/doxygen/dox/demos/high-speed-field-weakening.cxx sweeps the electrical speed through the solver and prints where each ceiling starts to bind:

  1// Field weakening -- above base speed: the voltage ceiling starts to bind, and the
  2// currents have to leave the MTPA curve to keep producing torque.
  3//
  4// Build it the way the `demo` gate does -- the example calls into the library, so the
  5// sources are part of the command, and `-Iinclude` alone fails at the link. A renamed
  6// source turns that gate red instead of leaving a stale instruction here:
  7//   g++ -std=c++17 -fno-exceptions -fno-rtti -Wall -Wextra -Werror -Iinclude
  8//   docs/doxygen/dox/demos/high-speed-field-weakening.cxx src/core/*.cpp
  9//   src/core/observer/*.cpp src/motor/*.cpp src/driver/*.cpp src/api/foc_api.c
 10//   src/api/bridge.cpp src/version.c
 11//   -o /tmp/high-speed-field-weakening
 12//
 13// With `--csv <path>` it writes the sweep as rows; `docs/demos/make_figures.py`
 14// draws this example's figure from that file.
 15//
 16// 弱磁 —— 基速以上：电压天花板开始约束，电流必须离开 MTPA 曲线才能继续出力。
 17// 带 `--csv <path>` 时把扫描写成行，供绘图脚本使用。
 18
 19#include <cmath>
 20#include <cstdio>
 21#include <cstring>
 22
 23#include <foc/core/machine_params.hpp>
 24#include <foc/core/mtpv.hpp>
 25#include <foc/core/types.hpp>
 26
 27namespace {
 28
 29constexpr float kVBusV = 24.0F;
 30
 31/// The voltage the modulator can actually deliver over a whole rotation: the
 32/// inscribed circle of its hexagon, not the rail. The
 33/// modulation-limits example draws why those differ.
 34/// 调制器在整个旋转上都保证得住的电压：它六边形的**内切圆**，不是母线电压。两者为何不同见 modulation-limits 示例。
 35constexpr float kVMaxV = kVBusV / 1.7320508F;
 36
 37} // namespace
 38
 39auto main(int argc, char** argv) -> int {
 40    const char* csv_path = nullptr;
 41    if (argc == 3 && std::strcmp(argv[1], "--csv") == 0) {
 42        csv_path = argv[2];
 43    } else if (argc != 1) {
 44        std::fprintf(stderr, "usage: %s [--csv <path>]\n", argv[0]);
 45        return 2;
 46    }
 47
 48    // A salient machine whose characteristic current is well above its current
 49    // ceiling: `lambda = Ld * i_max / psi_f` above 1 is the domain where field
 50    // weakening has somewhere to go. The four nameplate machines of this
 51    // repository sit below it, which is why this one is synthetic and says so.
 52    // 一台凸极机，其特征电流远高于电流上限：`lambda = Ld * i_max / psi_f` 大于 1 才是有弱磁
 53    // 余地的区域。本仓库的四台铭牌机都在这个值以下，所以这一台是合成的，并且它自己说出来。
 54    const foc::core::MachineParams machine{0.5F, 4.0e-3F, 8.0e-3F, 0.01F};
 55    const foc::core::MtpvConfig config{machine, kVMaxV, 3.0F, 7U};
 56    foc::core::Mtpv solver(config);
 57    if (solver.validate() != foc::ErrorCode::Ok) {
 58        std::fprintf(stderr, "the machine/ceiling combination was refused\n");
 59        return 1;
 60    }
 61
 62    const foc::core::MtpvPoint mtpa = solver.mtpa_point();
 63    const float base_speed = solver.base_speed_rad_s();
 64
 65    FILE* csv = nullptr;
 66    if (csv_path != nullptr) {
 67        csv = std::fopen(csv_path, "w");
 68        if (csv == nullptr) {
 69            std::perror("fopen");
 70            return 1;
 71        }
 72        std::fprintf(csv, "speed_ratio,id_a,iq_a,torque_nm,voltage_limited\n");
 73    } else {
 74        std::printf("nameplate: Ld 4 mH, Lq 8 mH, psi_f 0.01 Wb, i_max 3 A\n");
 75        std::printf("voltage ceiling %.3f V (the modulator's inscribed circle)\n", static_cast<double>(kVMaxV));
 76        std::printf("base speed %.1f rad/s elec -- from the flux at the MTPA point, not from psi_f\n\n",
 77                    static_cast<double>(base_speed));
 78        std::printf("MTPA point: id %+.4f A  iq %+.4f A  torque %.4f N.m  |i| %.4f A\n\n",
 79                    static_cast<double>(mtpa.id_a), static_cast<double>(mtpa.iq_a), static_cast<double>(mtpa.torque_nm),
 80                    static_cast<double>(mtpa.current_a));
 81        std::printf("%8s %10s %10s %10s %12s\n", "w/w_base", "id (A)", "iq (A)", "torque (N.m)", "voltage binds");
 82    }
 83
 84    // Sweep the electrical speed. Below base speed the answer does not move: the
 85    // current ceiling is the only one in force and MTPA is the best use of it.
 86    // Above it, the voltage ellipse starts to bind and the d current has to grow
 87    // negative -- trading torque per amp for headroom.
 88    // 扫电角速度。基速以下答案不动：只有电流上限生效，而 MTPA 是它的最好用法。基速以上电压
 89    // 椭圆开始约束，d 轴电流必须更负——用"每安培转矩"去换电压余量。
 90    int previous_limited = -1;
 91    for (int step = 0; step <= 200; ++step) {
 92        const float ratio = 0.1F * static_cast<float>(step);
 93        const float omega_e = ratio * base_speed;
 94        const foc::core::MtpvPoint point = solver.at_speed(omega_e);
 95        const int limited = point.voltage_limited ? 1 : 0;
 96        if (csv != nullptr) {
 97            std::fprintf(csv, "%.4f,%.6f,%.6f,%.6f,%d\n", static_cast<double>(ratio), static_cast<double>(point.id_a),
 98                         static_cast<double>(point.iq_a), static_cast<double>(point.torque_nm), limited);
 99        } else if (limited != previous_limited || (step % 20) == 0) {
100            std::printf("%8.2f %10.4f %10.4f %10.5f %12s\n", static_cast<double>(ratio),
101                        static_cast<double>(point.id_a), static_cast<double>(point.iq_a),
102                        static_cast<double>(point.torque_nm), point.voltage_limited ? "yes" : "no");
103            previous_limited = limited;
104        }
105    }
106
107    if (csv != nullptr) {
108        std::fclose(csv);
109        std::printf("wrote %s\n", csv_path);
110        return 0;
111    }
112
113    // The number that decides whether field weakening is worth implementing at
114    // all, printed rather than asserted: `lambda`. The `domain` gate uses the same
115    // ratio, so a machine that lands outside it is a machine where field weakening is
116    // not worth doing.
117    // 决定"弱磁值不值得做"的那个数，打印出来而不是断言：`lambda`。`domain` 门用的是同一个
118    // 比值，所以落在这个范围之外的机器，弱磁不值得做。
119    const float lambda = (machine.ld * config.i_max_a) / machine.psi_f;
120    std::printf("\nlambda = Ld * i_max / psi_f = %.3f  (above 1: field weakening has room)\n",
121                static_cast<double>(lambda));
122    return 0;
123}

Three numbers in its output are the whole decision:

  • `lambda = Ld * i_max / psi_f` -- above 1 the characteristic current sits beyond the current ceiling, so there is headroom to trade away; below 1 the machine cannot be weakened into a useful region at all. It is the same ratio the project's own domain check uses.

  • base speed -- computed from the flux at the MTPA point, not from psi_f. psi_f alone overstates it several-fold on a salient machine, and a drive sized on that number finds the real ceiling when its current loop saturates.

  • the voltage binds at ... -- the ratio where the ellipse takes over. Below it the answer is constant; above it the currents move every step.

1.1.5.3. Where the numbers come from

  • The voltage ceiling is the modulator's inscribed circle, not the rail. The High speed and modulation page shows why those differ and by how much; using the rail here makes the whole region look wider than it is.

  • The current ceiling is per axis in the nameplate and per vector here. |i| is what the solver bounds.

  • The nameplate is linear unless a machine map is supplied. Saturation moves the real boundary, and machine_map is the library's way of saying so.

1.1.5.4. How it goes wrong

  1. Base speed taken from `psi_f`. Too high by the amount MTPA already spends on the d axis, and the error is largest exactly on the salient machines this page exists for.

  2. The voltage ceiling taken as the rail. The rail is only reachable at six angles of the rotation; a request sized to it clips five times a revolution and arrives as a sixth-order torque ripple rather than a fault.

  3. Field weakening commanded without a speed. The d current it asks for is a function of speed; a caller that applies the above-base answer below base speed gives away torque per amp for nothing.

  4. A machine outside the domain, treated as if inside. When lambda is below 1 the honest answer is "this machine cannot be weakened usefully", which is a sentence the page and the solver both say -- not a number pulled out of a solver that had to extrapolate.

1.1.5.5. Evidence

Three claim rows cover this page -- foc/core/field_weakening.hpp, foc/core/mtpv.hpp and foc/core/machine_map.hpp -- and the level this page may state is the minimum of those three. The numbers behind the boundaries are in those rows and in test_mtpv.cpp, not on this page.

What this page does not claim: a saturated machine's operating point. The law assumes constant Ld/Lq and carries no Rs term, which is what makes it closed-form and what moves the answer on a machine that saturates; and no agreement with a real machine between the rows of its map is claimed, because the law is measured against a curve whose second derivative is known.

1.1.5.6. Figure

The figure is produced by docs/demos/make_figures.py from this page's own example; the base-speed marker and the asymptote are both read from the run, not written into the plot. What it does not show is the machine: the nameplate here is linear and the currents are the solver's answer, so a real machine's path on this plane will bow where its inductances saturate.
