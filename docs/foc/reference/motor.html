motor

The instance that owns a control loop. It is one type, and the loop is a template: the observer, the modulator, the regulator and the HAL are type parameters, so the whole tick inlines into your translation unit and nothing in the control path is an indirect call.

The shape

template <typename Observer, typename Modulator, typename Controller, typename HalPolicy,
          typename RefGenerator   = core::NullReferenceGenerator,
          typename FeedForward    = core::NullFeedforward,
          typename PositionControl = core::NullPositionControl,
          typename Aligner        = core::NullAlignment,
          typename Trace          = core::NullTrace>
class Motor;

The four leading parameters have no default, because a drive that has not chosen an observer has not chosen how it knows the angle. Everything after them is an inert default: present in the type system, costing nothing, replaceable one at a time.

Policies is how those parameters arrive at run time — one instance per control axis plus the speed loop:

struct Policies {
    Observer observer;
    Modulator modulator;
    Controller current_d;
    Controller current_q;
    Controller speed;
    RefGenerator reference{};
    FeedForward feed_forward{};
    PositionControl position{};
    Aligner align{};
    /* Trace */ trace{};
};

Two regulators for the current and one for the speed is not an accident of naming: the two current axes have different plants once decoupling is in place, and a shared integrator would make the d-axis disturbance visible on the q axis.

tick() is the only function that must be called at a fixed rate, and it is the only one that touches the HAL. Everything else may be called from a slower context.

the outer loop; the speed reference it produces is what the speed loop sees

an additive iq term

set once and it stays; set_speed() deliberately does not clear it

begin_stall_start(recipe) / cancel_stall_start()

the breakaway sequence

the caller owns the axis again as soon as the sequence releases it

The one rule that costs integrators a day: after a start-up sequence releases the axis, the caller must command something in the same control period, or the start-up torque keeps being applied.

Readback

  • telemetry() — speed_mech_rad_s, id_a, iq_a and max_period_us. That last field is the worst tick interval the target itself has seen: the number belongs to the chip, which is why it is measured here rather than published anywhere.

  • state() — the state-machine state; status() — the first error since the last clear.

  • mode() — which reference is in force.

  • fault_code() — the fault in the library's own vocabulary.

Policies are reachable after construction — observer(), reference(), feed_forward(), position(), aligner() — because a drive that cannot ask its observer what it thinks at run time cannot be commissioned.

Configuration

MotorConfig is the machine plus the setup decisions that go with it: rs, ld, lq, kt, j, b (the nameplate, in SI units), pole_pairs, then the limits and timing that belong to the installation — i_max_a, pwm_freq_hz, deadtime_ns, and the decimation periods of the two outer loops.

Two helpers turn that into gains without ever hiding a number:

Helper

What it derives, and from what

current_pi_config(config, bandwidth_rad_s, v_bus)

current-loop gains from rs/ld and the requested bandwidth; the output clamp comes from v_bus, not from a constant

speed_pi_config(config, bandwidth_rad_s)

speed-loop gains from kt and j — the two numbers that decide how fast the axis can be, and therefore how fast it may be told to be

position_p_config(config, bandwidth, velocity_limit, accel_limit)

the outer position gain plus the two limits the profile needs

psi_f_wb(config)

the flux linkage behind kt: kt / (1.5 * pole_pairs). Using kt directly in a voltage equation is dimensionally wrong

The whole tick, in one object

drive_supervisor.hpp is the assembly around the parts: one tick that reads the bus, runs the protection, drives the chopper and only then lets the control loop have its turn. It exists because the order is the claim — a protection evaluated after the loop has already commanded is a protection that arrives one tick late — and because the status it returns has to name a cause: the derated limit, the temperature that produced it (NaN when no channel answered), the bus voltage, the chopper's duty and the tick number.
