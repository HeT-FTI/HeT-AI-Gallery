1. Quick start

From an empty directory to a running control loop, in four steps. The deep reference — all three faces, the model, the verification matrix — lives in Usage and verification.

1.1. 1. What you need

Item

Requirement

Dependency manager

Conan 2.x (conan --version)

Build system

CMake; the exact floor is metadata.json → cmake_version

Compiler

C++17 and C11 (GCC / Clang / MSVC)

Library dependencies

etl (fixed-capacity containers, header-only); GTest for tests (host only); pybind11 for the Python module (host only, skipped on cross builds)

A consumer of the package does not need Sphinx or Doxygen — those build this documentation.

1.2. 2. Consume the package

Code 1.1 conanfile.py
def requirements(self):
    self.requires("foc/0.1.0")
Code 1.2 CMakeLists.txt
find_package(foc REQUIRED)
add_executable(app main.cpp)          # C users write main.c, the link rule is identical
target_link_libraries(app PRIVATE foc::foc)

There is exactly one link rule: the aggregate target foc::foc. It carries both foc::foc_c and foc::foc_cpp, and the package metadata guarantees the order.

警告

A C consumer still links the C++ runtime. The ABI is stable, the implementation is C++: set LINKER_LANGUAGE CXX (or add one empty .cpp), otherwise the link fails on __cxa_*. This is a documented boundary, not an accident.

1.3. 3. Pick a face

  • C++17 — board-level work, your own HalPolicy, your own gains: see the C++ path.

  • C11 — non-C++ projects and glue code over the frozen ABI: see the C path.

  • Python — host-side scripts on top of the C API: see the Python path.

Each snippet on that page is complete enough to compile, and the C and Python faces run on the stub HAL with library defaults (20 kHz, 500 ns dead time, 5 A limit, 24 V bus).

1.4. 4. From zero to a servo, in one file

The file below is the shortest complete example: a dq machine in Python behind the HAL callback protocol, the library's own speed loop closed on it, one speed step, and an assertion on where the axis landed. It is not a copy of an example -- it is the example, and the test suite executes it, so this page cannot drift from working code:

  1"""From zero to a running servo, in one file -- and this file is executed by the test suite.
  2
  3The quick-start page includes this source verbatim, so there is exactly one copy of the example: if it stops working,
  4a test fails; if the API changes, the page cannot keep showing the old one. Everything below uses only the public
  5Python module, and every limit it meets on the way is one of the documented boundaries.
  6
  7    python from_zero_to_servo.py     # runs the step and prints what the axis did
  8
  9从零到一个能跑的伺服，一个文件——而这个文件由测试套件执行。
 10
 11快速上手页原样包含这份源码，于是示例只有一份：它若失效，测试会失败；API 若改变，页面也不
 12可能继续展示旧的。下面全部只用公开的 Python 模块，途中遇到的每一条限制都在文档的边界页里。
 13"""
 14
 15from __future__ import annotations
 16
 17import math
 18
 19import foc_python as foc
 20
 21# The machine: a small salient PMSM. Every number is SI, as the library's params struct requires.
 22# 电机：一台小型凸极 PMSM。全部为 SI 单位，与库的 params 结构所需一致。
 23RS = 0.35
 24LD = 2.0e-4
 25LQ = 4.0e-4
 26KT = 0.05
 27J = 1.0e-4
 28B = 1.0e-3
 29POLE_PAIRS = 7
 30
 31V_BUS = 24.0
 32CONTROL_HZ = 20000.0
 33DT = 1.0 / CONTROL_HZ
 34SUBSTEPS = 8
 35
 36
 37def _clarke(du: float, dv: float, dw: float) -> tuple[float, float]:
 38    """Phase to stationary two-axis, the same convention the library uses internally."""
 39    return du, (du + 2.0 * dv) / math.sqrt(3.0)
 40
 41
 42def _inverse_clarke(alpha: float, beta: float) -> tuple[float, float, float]:
 43    return alpha, -0.5 * alpha + 0.5 * math.sqrt(3.0) * beta, -0.5 * alpha - 0.5 * math.sqrt(3.0) * beta
 44
 45
 46class PmsmPlant:
 47    """The machine behind the HAL callback protocol.
 48
 49    The library writes a duty cycle and reads currents, an angle and a speed. Nothing here knows about dq control: it is
 50    a physical model plus the three numbers a drive would measure.
 51
 52    库通过 HAL 回调协议驱动它：写入占空比，读回电流、角度与转速。这里没有任何 dq 控制：它是物理模型加上一台真实
 53    驱动器会测到的三个量。
 54    """
 55
 56    def __init__(self) -> None:
 57        self.theta_mech = 0.0
 58        self.omega_mech = 0.0
 59        self.id = 0.0
 60        self.iq = 0.0
 61        self.duty = (0.5, 0.5, 0.5)  # 50 % is zero volts on all three phases
 62
 63    # --- the HAL reads: names the binding looks up on this object ---
 64    def read_current(self) -> tuple[float, float, float]:
 65        theta_e = POLE_PAIRS * self.theta_mech
 66        cos_t, sin_t = math.cos(theta_e), math.sin(theta_e)
 67        alpha = self.id * cos_t - self.iq * sin_t
 68        beta = self.id * sin_t + self.iq * cos_t
 69        return _inverse_clarke(alpha, beta)
 70
 71    def angle_mech_rad(self) -> float:
 72        return self.theta_mech
 73
 74    def velocity_rad_s(self) -> float:
 75        return self.omega_mech
 76
 77    def voltage_v(self) -> float:
 78        return V_BUS
 79
 80    # --- the HAL writes -------------------------------------------------
 81    def write_duty(self, du: float, dv: float, dw: float) -> None:
 82        self.duty = (du, dv, dw)
 83        self._advance(DT)
 84
 85    # --- the physics ----------------------------------------------------
 86    def _advance(self, interval_s: float) -> None:
 87        """Fixed-step integration of the dq model, `SUBSTEPS` times per control period."""
 88        v_u, v_v, v_w = ((d - 0.5) * V_BUS for d in self.duty)
 89        v_alpha, v_beta = _clarke(v_u, v_v, v_w)
 90        theta_e = POLE_PAIRS * self.theta_mech
 91        cos_t, sin_t = math.cos(theta_e), math.sin(theta_e)
 92        v_d = v_alpha * cos_t + v_beta * sin_t
 93        v_q = -v_alpha * sin_t + v_beta * cos_t
 94        psi_f = KT / (1.5 * POLE_PAIRS)
 95        h = interval_s / SUBSTEPS
 96        for _ in range(SUBSTEPS):
 97            omega_e = POLE_PAIRS * self.omega_mech
 98            d_id = (v_d - RS * self.id + omega_e * LQ * self.iq) / LD
 99            d_iq = (v_q - RS * self.iq - omega_e * LD * self.id - omega_e * psi_f) / LQ
100            torque = 1.5 * POLE_PAIRS * (psi_f * self.iq + (LD - LQ) * self.id * self.iq)
101            d_omega = (torque - B * self.omega_mech) / J
102            self.id += d_id * h
103            self.iq += d_iq * h
104            self.omega_mech += d_omega * h
105            self.theta_mech += self.omega_mech * h
106
107
108def run_speed_step(command_rad_s: float, seconds: float = 0.4) -> dict[str, float]:
109    """Close the library's own speed loop on the plant above and step the speed.
110
111    Why the plant reports a velocity as well as an angle: with an angle but no speed the library would take the speed
112    from an observer, and the observer would be starting from zero -- a different example (the sensorless one), with its
113    own boundaries. This is the sensored path.
114
115    为什么这里既报角度也报转速：只给角度的话，库会从观测器取转速，而观测器是从零起步的——那是另一个例子（无感的那
116    一个），有它自己的边界。这里是带传感器的路径。
117    """
118    params = foc.MotorParams()
119    params.rs, params.ld, params.lq = RS, LD, LQ
120    params.kt, params.j, params.b = KT, J, B
121    params.pole_pairs = POLE_PAIRS
122
123    plant = PmsmPlant()
124    peak = 0.0
125    worst_settled = 0.0
126    ticks = int(seconds / DT)
127    settle_from = ticks - int(0.1 / DT)
128    with foc.Motor(params, plant) as motor:
129        motor.enable()
130        motor.set_speed(command_rad_s)
131        for tick in range(ticks):
132            motor.tick(DT)
133            peak = max(peak, plant.omega_mech)
134            if tick >= settle_from:
135                worst_settled = max(worst_settled, abs(plant.omega_mech - command_rad_s))
136        telemetry = motor.telemetry()
137        status = motor.status()
138    return {
139        "command_rad_s": command_rad_s,
140        "finished_rad_s": plant.omega_mech,
141        "peak_rad_s": peak,
142        "worst_settled_rad_s": worst_settled,
143        "iq_a": telemetry["iq_a"],
144        "observer": status["observer"].name,
145        "observer_locked": bool(status["observer_locked"]),
146    }
147
148
149def test_the_example_settles_a_speed_step() -> None:
150    # The bands are measured, not wished for. On this machine and this tuning the axis lands 0.007 rad/s short of a 20 rad/s step, peaks 1.3 % high, and never leaves a 0.14 rad/s band over the last 100 ms. The residual is mechanical, not control: with a rotor this light a few milliamps of current ripple is a fraction of a percent of speed, which is what the boundaries page says about the low-speed ripple in the sensorless case as well. A change that breaks these is a change in the library's behaviour and has to be looked at, which is the whole reason the page includes this file instead of a copy of it.
151    # 这些带子是量出来的、不是许愿的。在这台机器与这套整定下，轴比 20 rad/s 阶跃少 0.007 rad/s、峰值高 1.3%，最后 100 ms 内不离开 0.14 rad/s 的带子。残余是机械的、不是控制的：转子这么轻时，几毫安的电流纹波就是零点几个百分点的转速——这与边界页关于无感低速纹波的说法是同一件事。破坏它们的改动都是库行为的改变、必须被查看——这正是页面包含这个文件而不是副本的全部理由。
152    result = run_speed_step(command_rad_s=20.0)
153    assert abs(result["finished_rad_s"] - 20.0) < 0.05, result
154    assert result["worst_settled_rad_s"] < 0.20, result
155    assert result["peak_rad_s"] < 20.6, result
156    assert result["observer"] == "BACK_EMF", result
157    assert result["observer_locked"] is True, result
158
159
160if __name__ == "__main__":
161    outcome = run_speed_step(command_rad_s=20.0)
162    print(f"commanded {outcome['command_rad_s']:.1f} rad/s, finished at {outcome['finished_rad_s']:.3f} rad/s")
163    print(f"  peak {outcome['peak_rad_s']:.3f} rad/s, worst settled error {outcome['worst_settled_rad_s']:.4f} rad/s")
164    print(f"  q-axis current {outcome['iq_a']:.3f} A, observer {outcome['observer']}")

Run it yourself with the module on the path:

PYTHONPATH=$(dirname <the built foc_python*.so>) python3 test_package/test/python/from_zero_to_servo.py

It prints what the axis did. Measured on this machine: it lands 0.007 rad/s short of the 20 rad/s command, peaks 1.3 % high, and stays inside a 0.14 rad/s band over the last 100 ms -- the residual being mechanical ripple rather than a control error, which is one of the documented limits.

What it deliberately is not: a sensorless example (the plant reports a velocity, so the library takes the angle and the speed from it), and a proof of accuracy on your machine. Both are covered where they belong -- the injection observer and its boundaries, and the SIL tests that measure the loop against a plant.

1.5. 5. Prove it yourself

# build the package and run every test (unit, SIL, stress, pure-C and Python consumers)
conan create . -s build_type=Debug --build=missing

# quality gates: clang-format, clang-tidy, layering, standalone headers
python3 .github/misc/gates.py format
python3 .github/misc/gates.py tidy
python3 .github/misc/gates.py guard
python3 .github/project/gates.py strict

# negative compilation: a fake HAL must NOT compile
python3 .github/project/negative_compile.py

# coverage gate (reads the summary the recipe exports)
python3 .github/project/coverage_gate.py

# bilingual documentation (needs sphinx and a loadable doxygen)
python3 docs/build.py

What is deliberately not verified — dead-time compensation, ADC timing, EMI, ISR worst-case time, flash/RAM footprint — is listed item by item under honest limits.
