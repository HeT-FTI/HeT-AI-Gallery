End-to-end integration example

This example shows the stable CNN integration path without host-only allocation or file dependencies. Replace model symbols and buffers with generated assets.

Model and memory

#include "ie_api.h"

static ieUT8 app_pool[APP_POOL_BYTES];
extern const char app_strata[];
extern const char app_magma[];

IeSessionConfig cfg = {0};
cfg.pBackend = ie_backend_init(NULL, NULL, NULL, 0u);
cfg.pGeology = app_strata;
cfg.pMagma = app_magma;
cfg.geologyBytes = 0u;

size_t required = 0u;
if (ie_session_query_memory(&cfg, &required) != IE_SC_OK ||
    required > sizeof(app_pool)) {
    /* Invalid model or insufficient pool. */
}

cfg.pPool = app_pool;
cfg.poolSize = sizeof(app_pool);

Inference

IeSession *session = NULL;
if (ie_session_create(&cfg, &session) == IE_SC_OK) {
    IeVolcano *graph = ie_session_get_graph(session);
    const void *inputs[] = { app_input };

    ieStaCode status = ie_evoke(graph, inputs);
    if (status == IE_SC_OK) {
        status = ie_erupt(graph);
    }
    if (status == IE_SC_OK) {
        const void *output =
            ie_graph_get_output((const IeGraph *)graph, 0u);
        /* Consume or copy output before session destruction. */
    }
    ie_session_destroy(session);
}

The model and pool must be correctly aligned. Input data must already match the model dtype and quantization parameters; ie_evoke only copies it.

Optional registry path

For registry-based kernels, survey with the registry backend and resolve once before execution:

ie_registry_resolve(graph,
                    IE_HW_CPU | IE_HW_ARM_NEON,
                    IE_LAYOUT_BIT(IE_LAYOUT_CANONICAL));

The target build must include the corresponding component and ISA feature. If no optimized kernel accepts a layer, the canonical CPU implementation is selected instead.

Validation evidence

A valid integration demonstrates:

  1. output agreement with an independent reference;

  2. query/create memory consistency and intact canaries;

  3. identical output with and without optional fast scratch;

  4. independent behavior of two sessions;

  5. identical scalar, SIMD, and delegate results;

  6. target-board timing and memory measurements for any performance claim.

Complete examples are available under examples/. LLM integration follows a similar query/create pattern through IeLlm or the Qwen3-specific API.
