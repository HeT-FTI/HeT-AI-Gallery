API reference

The public headers under include/api are the final signature reference. Applications should not depend on private structure sizes or layouts.

Backend and CNN graph

ie_backend_init selects the configured backend. The usual pool-based product call is ie_backend_init(NULL, NULL, NULL, 0).

Session API

IeSession partitions an application pool and owns the mutable CNN session state.

ie_session_query_memory or ie_session_query_memory_report
-> ie_session_create
-> ie_session_get_graph
-> ie_evoke / ie_erupt
-> ie_session_reset or ie_session_destroy

The query and create operations must use the same model and configuration. Vision models normally leave KV, workspace, IO, and maxSeq at zero.

Generic LLM API

IeLlmDesc references the IEM blob, pool, role table, and runtime options. The generic adapter currently executes the Qwen3-compatible family.

The Qwen3-specific ie_qwen3_* API additionally exposes synchronous and asynchronous weight readers, weight windows, group scale formats, and KV configuration.

Sampling and tokenizer

IeSamplerConfig supports temperature, top-k, top-p, and repetition penalty. Random sampling requires caller-provided random state and vocabulary-sized work buffers.

Tokenizer functions bind IEM vocabulary, encode/decode text, and emit complete UTF-8 sequences incrementally. Chat rendering supports only the bounded operations serialized into IEM; it is not a general Jinja engine.

Ownership and concurrency

  • Model, weight, vocabulary, input, and output pointers are borrowed unless an API explicitly states otherwise.

  • The pool must outlive its session. Destroy does not free the pool.

  • Prefill, decode, reset, and destruction of one session are not concurrent operations.

  • Independent sessions need independent writable pools and scratch buffers.

  • Fast scratch is temporary workspace, not a persistent or thread-safe cache.
