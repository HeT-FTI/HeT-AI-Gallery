3. 元数据参考

3.1. metadata.json 的角色

metadata.json 是项目的控制平面。它驱动包身份、编译标准、依赖组合、文档语言与版本过滤以及 CI 工作流触发。

3.2. 核心身份字段

  • name、version、license、description

  • authors、maintainers、url、homepage

  • topics

这些字段会被 Conan 包元数据与发布产物消费。

3.3. 构建与运行时控制

  • build_cppstd 与 build_cstd 定义 CMake 目标使用的语言标准。

  • is_shared 与 is_header 控制打包模式。

  • activate_code_coverage 控制库与测试中的覆盖率插桩标志。

  • enable_python_bindings 控制 pybind11 及 Python 模块产出开关。

3.4. 依赖映射

dependencies 字段按使用域分组：

  • common：由 C 与 C++ 层共享。

  • c：面向 C 接口的补充链接依赖。

  • cpp：C++ 运行时补充依赖。

  • infra：测试与构建阶段的集成依赖。

这些分组会在 conanfile.py 中合并为最终 CMake 链接元组。

3.5. 文档控制项

  • doc_languages：启用语言集合（当前为 en 和 zh）。

  • doc_versions：Doxygen 过滤使用的版本通道。

  • doc_doxygen_folders 与 doc_doxygen_suffix：源码扫描范围。

文档流水线在生成 Doxygen 与 Sphinx 输出时会读取这些字段。

3.6. 工作流触发器

workflow_triggers 包含 build、tests、release、docs 与 security_scan 的布尔开关。CI 编排会消费这些开关以确定启用哪些工作流。
