2. Conan 配方配置

2.1. 目标

Conan 配方是 NNSeg 的权威打包流水线。它将 metadata、依赖、构建设置与验证步骤统一映射为可复现的包构建过程。

2.2. 生命周期概览

PackageRecipe 类会执行以下阶段：

  1. 从 metadata.json 初始化元数据与包身份。

  2. 从 conandata.yml 加载依赖需求。

  3. 生成 CMake 工具链与依赖文件。

  4. 使用 CMake 构建项目。

  5. 对产出的归档库执行兼容性校验。

  6. 通过 Conan 测试流程执行 test_package。

2.3. 依赖策略

  • 依赖项在 conandata.yml 中声明。

  • metadata 的分类（common/c/cpp/infra）决定 CMake 目标的链接方式。

  • GTest 仅保留在测试阶段使用，不进入运行时链接组。

  • 仅在启用 Python 绑定时才启用 pybind11。

  • 在裸机场景交叉编译模式下，依赖会按 baremetal_white_list 过滤。

2.4. 生成与验证

配方会生成 CMakeToolchain 与 CMakeDeps 产物，并使用工具链 binutils 校验生成的静态库。构建过程中会输出 JSON 格式的兼容性报告。

2.5. 常用命令

# Debug package + tests
conan create . -s build_type=Debug --build=missing

# Release package
conan create . -s build_type=Release --build=missing

# Cross build example (profile names are project-specific)
conan create . -pr:b=default -pr:h=arm_profile -s build_type=Debug --build=missing -tf=""
