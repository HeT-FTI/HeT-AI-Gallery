1. CMake 构建配置

1.1. 目标

根 CMake 配置定义了 NNSeg 的编译、链接与导出方式，用于包消费者集成。其流程由 metadata 驱动：项目名、语言标准、覆盖率模式与特性开关均来自 metadata.json。

1.2. 目标拓扑

在非纯头文件模式下，构建会生成三个目标：

  • nnseg_c：C 实现静态库（来自匹配 C 规则的源文件）。

  • nnseg_cpp：C++ 实现静态库（运行时引擎、模型封装与桥接代码）。

  • nnseg：接口目标，将 nnseg_c 与 nnseg_cpp 聚合为统一消费入口。

这种拆分在隔离 ABI 侧 C 代码的同时，保留了 C++ 内部实现的表达能力。

1.3. 依赖接线

CMake 通过 C_DEPS 与 CPP_DEPS 变量接收 Conan 传入的依赖链接信息。构建脚本会解析每个 package@target 元组，调用 find_package，并把解析得到的目标链接到正确的内部库。

1.4. 构建特性

  • C 与 C++ 标准由 metadata 中的 build_cstd 与 build_cppstd 字段控制。

  • 启用 activate_code_coverage 时会自动注入覆盖率编译标志。

  • 仅当 enable_python_bindings 为 true 时，才会从 api/python_bindings.cpp 构建可选 Python 绑定。

  • 仅当 build_cppstd >= 23 时才启用 C++ 模块支持。

1.5. 安装与下游使用行为

下游通过 Conan 生成的 CMake 包文件链接统一的 nnseg 目标。内部拆分目标仅为实现细节，下游 CMakeLists 无需直接依赖。
